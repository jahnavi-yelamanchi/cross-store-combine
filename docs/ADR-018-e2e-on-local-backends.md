# ADR-018: One end-to-end run on local backends proves the loop

- Context: CDC, policy, proposals API and ledger each have a smoke test, but none shows that a drifted record is detected, fixed exactly once and reproducible; replay seeds from a snapshot while demo drift is written straight to stores, outside the ledger.
- Decision: `xstore.pipeline.demo.run_demo` seeds postgres/mongodb/cosmosdb from a baseline snapshot, writes value-level injections (stale, typo, missing, type_drift, unit_mismatch) through `Store.write`/`delete`, pumps outboxes onto the `InProcessBus`, resolves each touched key with `PolicyEngine`, posts fixes to the FastAPI app via `TestClient`, auto-approves safe ones into the ledger, runs `apply_pending` twice and replays; `tests/e2e/test_e2e.py` (`-m e2e`) asserts the outcome. Replay seeds from `snapshot_injected`, written after injection, so it re-applies fixes to the same pre-fix state.
- Alternative rejected: recording injections as ledger events (they are external drift, not approved fixes; the ledger would stop meaning "what we changed"); replaying from the clean baseline (passes only because fixes are full-record upserts, so it would not catch a fix that depends on prior state).
- Why: one run over real adapters, outboxes, HTTP layer and SQLite ledger catches contract breaks between packages that per-package smokes miss, in about 2 s with no network.
- Consequence: replay verifies ledger chain integrity and that every applied fix reproduces its recorded read-back hash on the fields it wrote; it does not check whole-store equality or unfixed drift. Recall counts only injections that changed store state and still have a second witness; orders (Decimal lost in JSON snapshots), duplicates, orphans and schema drift are out of scope; sensitive-field fixes stay pending for review.

# ADR-023: Terraform AWS mapping of the local stack

- Context: the local stack runs Redpanda, Postgres, moto DynamoDB, local Parquet/Iceberg and an in-process CDC pump; a real deployment needs the same shape on AWS without changing `xstore` code.
- Decision: `terraform/aws` maps each piece to a managed service: MSK (3 x kafka.t3.small, SASL/IAM over TLS, KMS at rest; optional MSK Connect for `cdc/debezium/postgres-connector.json`), RDS Postgres 16 (`rds.logical_replication=1`, password in Secrets Manager), DynamoDB `xstore` with NEW_AND_OLD_IMAGES stream and PITR, S3 + Glue Data Catalog Iceberg table `xstore.customer` + Athena workgroup, a Lambda on the stream calling `handle_batch` with `ReportBatchItemFailures`, bisect and an SQS on-failure DLQ, and optional EKS with IRSA for the reconciler.
- Alternative rejected: managed policies such as AWSLambdaDynamoDBExecutionRole and AmazonS3FullAccess (grant every table/bucket in the account); a self-managed Iceberg REST catalog (another service to run, while Glue is what Athena reads natively).
- Why: least-privilege inline policies name concrete ARNs (one stream, one DLQ, one bucket, one Glue database, one workgroup, MSK topic/group ARNs), so a compromised Lambda or pod cannot reach other data; poison CDC records go to the DLQ after bisecting instead of blocking the shard.
- Consequence: the Lambda decodes into an in-process bus (poison detection only); forwarding to MSK needs a Kafka-backed bus; the DLQ holds failure metadata (shard, sequence range), so recovery re-reads the stream within its 24 h retention; the Lambda needs a layer with fastavro/pydantic/pyyaml; the Iceberg day(updated_at) partition spec is set by the writer, not Glue; providers could not be downloaded in the build sandbox, so `validate`/`plan` run in CI or with registry access.

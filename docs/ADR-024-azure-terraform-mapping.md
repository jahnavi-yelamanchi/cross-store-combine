# ADR-024: Azure mapping of the local stack in Terraform, keyless via Entra

- Context: the local stack (Redpanda + Schema Registry, Cosmos in-memory, ADLS Parquet, in-process bus, ADR-004/005/009) needs a real Azure target under `terraform/azure/` without changing the `Store` contract.
- Decision: azurerm 4.x modules map Kafka to the Event Hubs Standard Kafka endpoint (`xstore.changes` x6, `xstore.cdc.dlq`, Avro schema group `xstore`), Cosmos to a serverless Session account with `customers`/`batches`/`_xstore_applied`/`leases`, the lake to ADLS Gen2 `lake` queried by Synapse serverless (Parquet external table + Delta Lake via `OPENROWSET FORMAT='DELTA'` over `lake/batch_delta/`), the Cosmos change feed to a Flex Consumption Python function calling `handle_documents`, BlobCreated to Event Grid -> Event Hubs with blob dead-letter; every data-plane caller uses Entra RBAC (reconciler: user-assigned identity federated to the AKS OIDC issuer).
- Alternative rejected: SAS/connection strings and account keys in Key Vault; Confluent Cloud or Kafka on AKS; Databricks for Delta reads.
- Why: Event Hubs speaks the Kafka protocol, so Debezium configs only change bootstrap/auth; local auth is disabled on Event Hubs, Cosmos and storage, so there is no secret to rotate or leak; serverless SQL reads Delta logs without running a Spark pool.
- Consequence: Kafka clients must use SASL OAUTHBEARER with Entra tokens; the function forwards JSON envelopes (output bindings cannot do Avro + partition keys), Avro stays on the Debezium path; the Delta writer is not in this repo; AKS (`enable_aks`, default off) hosts the issue #48 chart.
